# 图像链路性能极限与参数表（DART H7 + OV5640）

日期：2026-11-12
目标：以 60 fps 为基线，测出**采集、算力、传输**各自的瓶颈与当前最优平衡点。

## 1. 测试环境与固件

- 板卡：DART Control H7（STM32H750，OV5640，320×240 RGB565，USB CDC）
- 固件：`build_local/Release/GMStdRobotLib.elf`（81,940 B Flash）
- 新增命令：`CAMERA REGS`、`CAMERA TIMING0..4`、`SNAP8`、`SNAP1`、`SNAPE`
- USB 发送优化：去掉忙等中的 `HAL_Delay(1)`，改为紧循环（提升小包吞吐）

## 2. 传感器当前寄存器（实测）

```text
0x3035=41 0x3036=60 0x3037=13 0x3108=01
HTS 0x380C/D = 0x0790 = 1936
VTS 0x380E/F = 0x0440 = 1088
曝光 0x3500/01/02 = 0x003D80 = 15744 lines
0x3503=00（自动曝光）  0x4837=22（PCLK 约 14.7 MHz）
0x3008=02（stream on）  0x4202=00
```

按 `fps = PCLK / (HTS × VTS)`：`14.7e6 / (1936 × 1088) ≈ 6.98 fps`，与实测采集 ~0.14–0.17 s/帧（约 6–7 fps）一致。

## 3. 格式/带宽/帧率实测（同一场景）

| 方案 | 每帧字节 | 采集等待 | USB 传输 | 单帧总耗时 | 帧率 | 瓶颈 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| RGB565 | 153,600 | 0.15–0.17 s | 0.315 s | 0.48 s | **2.07 fps** | 采集 + 传输 |
| 绿色差分 8-bit | 76,800 | 0.13 s | 0.085 s | 0.22 s | **4.3 fps** | 采集 |
| 绿色差分 1bpp | 9,600 | 0.14 s | 0.010 s | 0.152 s | **6.59 fps** | 采集 |
| 板上椭圆参数 | ~24 B | 0.16 s（含计算） | ≈0 | 0.163 s | **6.14 fps** | 采集 + 计算 |

USB 实测吞吐：

- 大包（RGB565）：153.6 KB / 0.315 s ≈ **487 KB/s**
- 中包（GREEN8）：76.8 KB / 0.085 s ≈ **903 KB/s**
- 小包（BIN1）：9.6 KB / 0.010 s ≈ **960 KB/s**

→ 优化后 USB 能力约 **0.9–1.0 MB/s**；60 fps 时每帧预算 **≤15 KB**。

## 4. 采集/时序参数尝试（寻找更高帧率）

| 配置 | HTS | VTS | 理论 fps（PCLK 14.7 MHz） | 实测 |
| --- | ---: | ---: | ---: | --- |
| 默认 | 1936 | 1088 | ≈7.0 | ✅ 正常（0.15 s/帧） |
| TIMING1 | 1936 | 800 | ≈9.5 | ❌ FRAME TIMEOUT |
| TIMING2 | 1200 | 800 | ≈15.3 | ❌ FRAME TIMEOUT |
| TIMING3 | 1000 | 800 | ≈18.4 | ❌ FRAME TIMEOUT |
| TIMING4 | 1000 | 612 | ≈24.0 | ❌ FRAME TIMEOUT |
| 60FPS 尝试 | 800 | 306 | ≈60 | ❌ FRAME TIMEOUT |

结论：**当前 OV5640 QVGA 配置下，修改 HTS/VTS 会导致不出帧**（运行中改时序/需要重新初始化或该模式对 HTS/VTS 有最小值限制）。
要真正提高采集帧率，需要：
1. 按 OV5640 数据手册重新配置 **PLL/PCLK + HTS/VTS**（并做完整 sensor re-init）；
2. 或改用更低分辨率模式（QQVGA 等，HTS/VTS 可更小）；
3. DCMI 改**连续模式 + 双缓冲**，去掉每帧 Stop/Start 的等待。

## 5. 算力瓶颈

| 处理 | 平台 | 实测/估计 |
| --- | --- | ---: |
| 检测 + PnP + Kalman（Vesna-Eye） | 上位机 | ≈2 ms/帧（720p）；QVGA 更快 |
| RGB565 → 绿色差分（76,800 px） | H750 | 约 10–30 ms（含在采集等待里） |
| 差分 → 1bpp 打包 | H750 | 约几 ms |
| 板上白盘矩椭圆（`SNAPE`） | H750 | 约 20 ms |

60 fps 预算 16.7 ms：**板上全幅逐像素转换会吃掉大部分预算**，需要查表/定点优化，或只处理 ROI。

## 6. 当前最优平衡点

在**不改传感器模式**的前提下：

| 目标 | 最优选择 | 说明 |
| --- | --- | --- |
| 最高帧率 | **1bpp 白盘掩膜**（9.6 KB） | 6.59 fps，传输仅 0.010 s，采集是唯一瓶颈 |
| 最高精度 | **JPEG q70（~13.5 KB）** | 影子实验 yaw/pitch 误差 ~0.03°；传输约 0.05 s |
| 最低带宽 | **板上椭圆参数（~24 B）** | 6.14 fps，采集+计算限制 |

- 传输能力 0.9–1.0 MB/s ⇒ 60 fps 允许 **≤15 KB/帧**：1bpp（9.6 KB）、JPEG q70（13.5 KB）都满足；RGB565/绿色差分 8-bit **不满足**。
- 当前 60 fps 的唯一硬瓶颈是**采集 ≈0.15 s/帧（≈7 fps）**，不是 USB，也不是上位机算力。
- 若把采集提升到 60 fps（16.7 ms），1bpp 白盘掩膜可跑满 60 fps（576 KB/s），JPEG q70 也可（810 KB/s，接近 0.9 MB/s 上限）。

## 7. 60 fps 路线（下一步）

1. **传感器 60 fps 模式**：按数据手册重配 PLL/PCLK、HTS/VTS，完整 re-init；目标 `fps = PCLK/(HTS×VTS) = 60`（例如 PCLK 48 MHz、HTS 800、VTS 1000；或 QVGA 下 HTS 1000/VTS 800 + PCLK 48 MHz）。
2. **DCMI 连续采集 + 双缓冲**：帧中断切换缓冲区，发送任务取最新帧，USB 忙则丢帧。
3. **负载格式**：白盘掩膜 1bpp（9.6 KB）或 ROI+JPEG（2–4 KB）。
4. **算力优化**：查表法 RGB565→差分/二值；必要时只处理 ROI。
5. 目标性能表：

| 配置 | 每帧 | 采集 | 传输 | 算力 | 预期 fps |
| --- | ---: | ---: | ---: | ---: | ---: |
| 320×240 1bpp 白盘掩膜 | 9.6 KB | 16.7 ms | 10 ms | ~10 ms | **60（需流水线）** |
| 96×96 ROI + JPEG q60 | 2–4 KB | 16.7 ms | 3–5 ms | ~5 ms | **60** |
| 320×240 JPEG q70 | 13.5 KB | 16.7 ms | 15 ms | ~5 ms | **≈55–60（临界）** |
| 320×240 RGB565 | 153.6 KB | 16.7 ms | 315 ms | — | 物理不可行 |

## 8. 结论

- **传输已不是瓶颈**（优化后 0.9–1.0 MB/s）；**采集是当前唯一硬瓶颈**（≈7 fps，受 OV5640 QVGA 时序限制）。
- **60 fps 可行格式**：1bpp 白盘掩膜（9.6 KB）或 ROI+JPEG（2–4 KB）；全幅 RGB565/绿色差分 8-bit 在 USB 上不可能。
- 要跑到 60 fps，必须先解决 **OV5640 60 fps 时序/PLL 配置 + 连续采集双缓冲**；之后 1bpp/ROI-JPEG 都能满足带宽。
- 当前固件已保留 `CAMERA REGS`、`CAMERA TIMING0..4` 命令，便于继续扫时序参数。
